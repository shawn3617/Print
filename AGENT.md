## Порядок работы
1. **В начале каждого нового чата** — прочитать `state.md` (и этот файл). Не начинать работу, не сверившись с ним.
2. **Мелкие шаги.** Одна задача — одно законченное изменение. Не переписывать всё приложение сразу.
3. **Менять только то, что относится к задаче.** Не переписывать рабочие места «заодно». Увидел другую проблему — сообщи мне, не чини молча.
4. **Не выдумывать.** Имена полей СПДС, теги атрибутов, свойства COM, координаты граф штампа — только из реальных данных (DXF, дамп объекта, JSON-экспорт с полем `fields`, мой скриншот). Нет данных — попроси у меня пример, это дешевле, чем три круга «не работает».
5. **Перед тем как сказать «готово»:** проверить синтаксис (`python -m py_compile <файл>`), для LISP — баланс скобок и кавычек. Где можно — проверить логику на моих данных (DXF/JSON) без AutoCAD.
6. **После изменения — инструкция для теста:** что запустить, что нажать, что должно получиться. Команда запуска всегда: `python -m ui.main_window` из корня проекта (не `python ui/main_window.py`). Жди моего ответа перед следующим шагом.
7. **Объясняй коротко:** что было не так, что изменено, в каких файлах. Без длинных пересказов кода.
8. **Ошибки не глотать молча.** Никаких `except: pass` там, где от результата зависит печать. Либо понятное сообщение пользователю, либо `print` в консоль с причиной.
9. **После задачи — дописать в `state.md`** раздел «Сделано (журнал)» и при необходимости «Известные ограничения» / «TODO». Не переписывать весь файл без необходимости.
10. **Длинный чат.** Если диалог разросся (много логов, приближается сжатие контекста) — обновить `state.md` и предложить новый чат.

## Технические грабли проекта (уже наступали — не повторять)
1. **LISP-файлы (`core/lisp/*.lsp`) — в кодировке Windows-1251.** Не пересохранять в UTF-8: ломаются русские имена полей СПДС («Лист», «Масса», «Масштаб»). JSON от LISP читать в `cp1251`.
2. **В AutoLISP `"\\""` — не кавычка**, а строка из `\` и начало новой строки: ломает разбор всего файла. Кавычка внутри строки: `"\\\""`.
3. **Пути внутри LISP-выражений — только прямые слэши** (функция `lisp_str()` в `parsers/base_parser.py`). В exe путь вида `C:\...\_internal\core\lisp` с `\` ломает `load`.
4. **`fix` в AutoLISP падает на огромных вещественных** (`fixnump`): перед `fix` проверять диапазон.
5. **COM-объекты (`CDispatch`) нельзя класть в `set` и делать ключами `dict`.** Ключ — путь (`FullName`), `Handle` или `Name`.
6. **Любое обращение к AutoCAD — через `_retry_busy`** (`core/autocad_connector.py`). В exe «AutoCAD занят» приходит как `AttributeError` (`<unknown>.Count`, `Open.ModelSpace`, `Item.ModelSpace`), старый `com_retry` его не ловит. Настоящие COM-ошибки («Неверный ввод») не повторять.
7. **Объект из `Documents.Open` сразу не использовать** — ждать готовности AutoCAD и брать документ из `Documents` по пути (`open_document` так и делает).
8. **`SendCommand` выполняется в активном чертеже** — перед ним активировать нужный и дождаться `GetAcadState().IsQuiescent` (`_run_lisp_export`).
9. **Проверять поведение не только из VS Code, но и в собранном exe:** другие пути (`sys._MEIPASS`), нет кэша типов win32com.
10. **Формат рамки неоднозначен:** A2 М1:100 = A4 М1:200 = почти A0 М1:50 (форматы A подобны). Не брать первый подходящий — см. `choose_candidate` в `polyline_parser.py`.
11. **Рамки-полилинии бывают незамкнутыми** (флаг 0, 5 вершин). Не фильтровать по `Closed`.
12. **СПДС: номер и наименование — строго по форме штампа** (см. `state.md`). `Name 1..6` — фамилии «Согласовано», `DrawingName1` у формы 3 — здание. Не перебирать «все похожие поля».
13. **Плоттер `.pc3` из AutoCAD 2024 не читается в 2021** — плоттеры хранятся по версиям: `plotters\<год>\`.
14. **Чертежи, открытые программой, не закрывать** после печати (принятое решение).

## Сборка
- Только через **`build.bat`** (точка входа `run_app.py`, режим `--onedir`, результат `dist\PrintPDF\`). Новые `.spec` не создавать, PyInstaller вручную не запускать.
- Новые ресурсы (не `.py`) добавлять в `build.bat` строкой `--add-data "папка;папка"` и читать через `get_resource_path`.
- Новые библиотеки — в `requirements.txt`, ставить в `.venv`.

## Окружение
- Windows, AutoCAD 2021 (R24.0) и 2024 (R24.3), русские; СПДС GraphiCS.
- Python + `.venv`, `win32com` (pywin32), Qt-интерфейс (`ui/main_window.py`), `pypdf`.
- Git: служебное (`build/`, `dist/`, `*.spec`, `__pycache__`, `.venv`) — в `.gitignore`, не коммитить.
